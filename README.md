## AI Systems & Agentic Engineering

Technologies are grouped by purpose and labeled honestly. **Working with** means hands-on use in projects or internships. **Exploring** means active learning and experimentation, not claimed mastery.

### Compact Language Models (~3B parameters)

Models in the roughly 3-billion-parameter class, such as **Qwen2.5-3B** and **Llama 3.2 3B**, are appealing for resource-conscious inference, local experimentation, privacy-sensitive architectures, and lightweight AI workflows. With quantization, they can run on modest hardware.

Parameter count is only one factor. Model size, memory requirements, output quality, and task suitability are separate questions, and a compact model can fall short of larger ones on complex reasoning. I treat evaluation on the actual task as part of the work. These are models I'm exploring; I have not trained or deployed one.

### Agent Engineering: Learning Areas

Concepts I'm studying and want to implement, not capabilities I'm claiming:

- Tool-using agents with structured tool outputs
- Stateful workflows and workflow persistence
- Context management; short-term and long-term memory patterns
- Human-in-the-loop approval
- Retry and error-handling strategies
- Agent evaluation, observability, and tracing

### Engineering Principles for AI Applications

Good AI applications need more than prompting. These are standards I aim to hold myself to:

- Deterministic software around probabilistic model output
- Input validation and structured outputs
- Permission-aware tool execution
- Explicit error handling and reliable fallback behavior
- Evaluation, observability, and awareness of latency and cost
